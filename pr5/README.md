# Практична робота 5. Семантичний пошук

Застосунок порівнює локальний семантичний пошук на `intfloat/multilingual-e5-small` з BM25. Мовна модель не генерує відповіді: пошук повертає фрагменти документів. API-ключ Google AI Studio для цієї роботи не потрібен.

## Запуск

```bash
cd pr5
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python check_env.py
python build_index.py
uvicorn app.main:app --reload
```

Відкрийте `http://127.0.0.1:8000`. Перший запуск `check_env.py` завантажить модель з Hugging Face; це може зайняти кілька хвилин і кількасот мегабайт. Якщо індексу немає, сервер усе одно стартує і пояснює, що потрібно виконати `python build_index.py`.

## Структура

- `docs/` — 16 Markdown-документів із JSON-метаданими: назва, категорія, товар, аудиторія, дата редакції та статус.
- `app/chunking.py` — читання метаданих і поділ за заголовками та абзацами з перекриттям.
- `app/embeddings.py` — локальна модель E5 із префіксами `passage:` і `query:`.
- `app/index_store.py` — матриця векторів у NumPy та маніфест JSON із моделлю, фрагментами й метаданими.
- `app/search.py` — повний перебір за косинусною схожістю та BM25.
- `app/main.py` — FastAPI і JSON API; веб-рівень не працює з моделлю або файлами індексу напряму.
- `compare/` — 15 контрольних запитів, скрипт вимірювання та звіт.

Фрагменти будуються всередині розділів, щоб не змішувати теми. До тексту ембедінгу додаються назва документа та заголовок, але у видачі показується саме уривок. Фільтри застосовуються перед ранжуванням. За замовчуванням API показує лише документи для клієнтів; внутрішні документи не відкриваються довільним фільтром. Для навчального перегляду персональних документів встановіть `ALLOW_INTERNAL_DOCS=true`; у реальній системі таке право має визначатися серверною роллю.

Час semantic включає кодування запиту та пошук. Час BM25 вимірюється окремо; оцінки BM25 і косинусної схожості мають різні шкали, їх не можна напряму порівнювати. Поріг застосовується лише до semantic.

## Порівняння

```bash
python compare/run_compare.py
```

Скрипт запускає обидва методи на одному наборі, рахує hit@1, hit@3, ранги очікуваного документа, оцінку першого результату вище за нього та час пошуку. Потім змінює лише розмір фрагмента з 900 до 200 символів і повторює прогін. Поріг semantic `0.784` обрано за контрольним набором: між мінімальною оцінкою запитів із відповіддю та оцінкою запиту поза колекцією. Фактичні таблиці й висновок записуються у `compare/findings.md`, сирі результати — у `compare/results.json`.

Вихідна папка `docs/` з архіву методички в наданому репозиторії відсутня, тому тут підготовлено окрему навчальну колекцію з 16 документів магазину «Сузір'я» з потрібними категоріями, товарами, статусами й аудиторіями.
