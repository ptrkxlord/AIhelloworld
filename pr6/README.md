# Практична робота 6. RAG-помічник

FastAPI-застосунок шукає відповіді в базі знань магазину «Сузір'я», передає обмежений контекст Gemini через OpenAI-сумісний API та перевіряє структуровану відповідь і посилання перед показом.

## Запуск

```bash
cd pr6
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

У `.env` вкажіть ключ Google AI Studio у `GEMINI_API_KEY`. Також підтримуються `LLM_API_KEY` і `LLM_MODEL` для сумісності з налаштуванням ПР3–ПР4. Ключ не додавайте до Git.

```bash
python check_env.py
python build_index.py
uvicorn app.main:app --reload --port 8001
```

Відкрийте `http://127.0.0.1:8001`. Без індексу застосунок запускається, але пояснює, як його створити. Індекс зберігається в `data/index/` і не потрапляє до Git.

## Архітектура

- `app/search.py`, `chunking.py`, `embeddings.py`, `index_store.py` — модулі пошуку та індексу, перенесені з ПР5 без зміни алгоритму.
- `app/context_builder.py` — клієнтська політика, фільтр товару, вибір фрагментів і бюджет контексту.
- `app/gemini_client.py` — OpenAI-сумісний клієнт Gemini, структурований формат відповіді й класифікація збоїв.
- `app/schemas.py` — схеми запиту та відповіді.
- `app/rag.py` — retrieval, складання контексту, генерація та перевірка посилань і чисел.
- `app/main.py` — HTTP API та стартове завантаження індексу.
- `app/static/index.html` — сторінка помічника, джерела, метрики й текст контексту.

Пошук допускає до контексту лише документи з аудиторією `клієнти`; `context_builder.py` повторює цю перевірку перед генерацією. У API немає фільтра аудиторії. Архівна редакція додається лише для явного запиту з роком 2025 або словами про архів/стару редакцію. У загальному запиті про чинні правила архів не передається моделі.

Поріг семантичного пошуку — `0.784` з ПР5. Пошук повертає ширший список кандидатів, контекст має окремі `CONTEXT_CHUNK_LIMIT=4` і `CONTEXT_TOKEN_BUDGET=1500`. Бюджет оцінюється за символами (`CHARS_PER_TOKEN=2.5`), бо точний токенізатор сумісного Gemini API тут не використовується. У відповіді Gemini токени беруться з `usage`, а пошук і генерація вимірюються окремо.

Код відхиляє неіснуючі номери джерел, `found=true` без джерел і числові значення, яких немає у процитованих фрагментах. Невалідна відповідь замінюється на безпечну відмову. Інші твердження перевіряються інструкцією моделі та очікуваними фактами eval-набору; це не формальна перевірка кожного речення і є обмеженням підходу.

## Перевірки

```bash
pytest -q
python -m eval.run_eval
```

`eval/scenarios.json` має 15 запитань із очікуваними джерелами, фактами й рішенням щодо відповіді. Скрипт проходить повний retrieval-to-generation pipeline, зберігає контекст, джерела, відповідь, час і токени в `eval/results.json`, а підсумок — у `eval/findings.md`. Він порівнює лише одну зміну: ліміт контексту 4 проти 2. Для повного прогону потрібні створений індекс і доступний ключ Gemini. Якщо провайдер відхиляє ключ, він виконує retrieval для решти сценаріїв без додаткових запитів до моделі та явно позначає генерацію як недоступну.

Відповіді на десять контрольних запитань: `eval/control_answers.md`.

## Колекція

Офіційний архів до ПР6 у робочій папці не був доступний. Для цілісного застосунку скопійовано ті самі 16 демонстраційних документів, що й у ПР5, включно з архівним правилом доставки та внутрішньою інструкцією. Це узгоджує структуру з вимогою завдання, але самі документи є навчальним корпусом, а не оригінальними файлами викладача.
